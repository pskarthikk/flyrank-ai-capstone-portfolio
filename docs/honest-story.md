# Honest build-in-public story

I built this portfolio because I wanted a place where I could show the work instead of repeatedly saying that I am learning AI and machine learning.

The biggest help from AI was not a single code snippet. It was having a partner that could turn a vague idea into a sequence of small decisions, explain unfamiliar implementation details, and help me iterate quickly. That let me spend more time deciding what the project should prove and less time getting stuck on implementation details.

The limitation was just as useful: AI can make a site look finished before the underlying claims have been checked. Metrics, links, edge cases, and what actually happened in the project still need human verification. I learned to treat AI output as a draft and the evidence as the source of truth.

One thing that failed my first pass was the boundary around the interactive ML demo. It was easy to make a working score calculator, but presenting it without enough context could make someone think it was the trained Random Forest itself. I changed the copy and documentation so the demo is clearly described as transparent decision logic, while the real model result stays in the case study.

The portfolio is deliberately simple. The goal is not to impress someone with a complicated frontend. It is to make the work easy to understand, let a stranger try one working feature, and give them somewhere to come back when I ship the next project.
